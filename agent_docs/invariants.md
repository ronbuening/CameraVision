# Project Invariants

Binding rules for any change, by any agent, at any level. If a task appears to require breaking one of these, stop and ask instead of proceeding. Each rule states the required behavior and the preferred path.

## Safety invariants (violations corrupt user data or trust)

1. **Analyze never touches XMP.** `aisidecar analyze` and every raw-sidecar path write only `.ai.json` artifacts. XMP creation/modification happens exclusively in the Phase 2 export engine — reached via `aisidecar write-xmp`, Phase 3 normalized export paths, and the GUI export surface (which fronts every write with a dry-run change plan). No new write paths. There is a regression test for this; keep it passing and keep it meaningful.
2. **Source images are never modified.** All output is sidecars and run artifacts. This includes RAW, JPEG, TIFF, HEIC, PNG, and DNG.
3. **GPS is model-input context only.** `--gps-context` may influence prompts and raw-sidecar provenance. Coordinates, GPS-derived location metadata, and GPS-only evidence must never become XMP keywords or embedded metadata. Enforce the shared keyword-safety policy at every route into XMP (model extraction, session context, review edits, imported sessions, and final planning). A visually depicted object such as a GPS receiver is not GPS-derived metadata; keep that distinction explicit and tested.
4. **XMP writes are guarded.** Every XMP write path goes through the owned engine with deterministic backups, source-hash rechecks, post-write validation, and restore-on-validation-failure. New export features plug into that chain, never around it.
5. **`--export-model-inputs` is diagnostic-only.** It writes rendered inputs and a manifest — no model calls, no sidecars, no progress logs, no summaries, no XMP.
6. **`cleanup` removes only owned artifacts.** Never source images, `.xmp` sidecars, XMP backups, model-input exports, debug derivatives, derivative-cache files, or normalization session JSON.

## Compatibility invariants (violations silently break downstream consumers)

7. **Stable raw strings.** Public enum raw values, error codes (`SidecarError`), schema identifiers, and artifact-name patterns are load-bearing: existing sidecars, logs, and sessions reference them. Add new values; never rename or reuse existing ones.
8. **Additive schemas.** Sidecar/session/report schema changes follow the established schema-evolution rewrite support. A document written by an older version must remain readable. When a same-major normalization session contains an unknown direct-decision enum, preserve its raw JSON, fail that decision closed, and never let review or planning re-enable it.
9. **Config precedence is fixed:** CLI flag > `AISIDECAR_*` environment > JSON config file > built-in default. `aisidecar purge` resolves only derivative-cache settings and must not depend on model/runtime config validity.
10. **Exact-first vocabulary matching.** Punctuation, possessive, ampersand, and final-token singular/plural fallbacks are ambiguity-guarded and must never override exact canonical, flat-keyword, or synonym matches. An ambiguous primary key is terminal: no fallback may reinterpret or rescue it. Exact canonical-path lookup remains authoritative.
22. **Sequential quality scans never perturb tagging.** (Numbered 22 to keep existing invariant numbers stable; belongs with this compatibility group.) With `quality_scan_mode = sequential`, the tagging pass runs the plain tagging contract and its `.ai.json` output must stay byte-identical to a run without assessment; quality lands only in the paired `.quality.ai.json`. The `quality_scan_mode` provenance key is encoded only when it departs from the `combined` default, so sidecars from runs that never chose a mode keep their pre-feature bytes (golden/hash identity tests pin both halves). Do not fold the two passes back into one call or start recording the default.

## Platform and process invariants

11. **macOS 15 minimum, Swift 6 strict concurrency, macOS-only.** No cross-platform availability annotations or platform docs unless a requirement broadens support.
12. **Tests are deterministic and offline.** Unit tests must not require Ollama, model downloads, real images, or network. Use the mock runners and recorded fixtures in `ModelRuntime` and `Tests/AISidecarCoreTests/Fixtures/`.
13. **Core/CLI/GUI split.** Reusable behavior goes in `Sources/AISidecarCore`; `Sources/AISidecarCLI` is argument parsing, command wiring, and presentation only. The GUI target `Sources/CupricAspectApp` follows the same rule: presentation, state orchestration, and user interaction only — all processing stays in Core (FR4-002).
14. **Two executables, fixed shapes.** The CLI is one `aisidecar` binary with phase-specific subcommands — never split it into multiple CLI tools. The GUI is the separate `CupricAspect` executable (Phase 4, added at its M0). Do not add further executable products without an explicit requirement.
15. **Ollama capability preflight stays serial.** A parallel version was deliberately reverted (commit `a1366b6`). Do not re-parallelize it.
16. **Behavior changes ship with tests.** Prefer focused unit tests in `AISidecarCoreTests`. Follow `agent_docs/commenting_guide.md` for any substantive comments or public API docs.
17. **One milestone / one work item at a time** unless the user explicitly expands scope. Phase 1 Milestones 0-9a, Phase 2 Milestones 0-10, Phase 3 Milestones 0-11, and Phase 4 GUI milestones M0–M8a plus beta-readiness items B0-1–B0-4/B0-6 are complete — do not reopen released milestone work without new acceptance criteria.
18. **Resource loads go through `AISidecarResourceBundle.current`, never `Bundle.module` directly.** SwiftPM's generated accessor fails when an executable is relocated (the WI-2 packaging bug). The locator's search order is app `Contents/Resources` → executable-adjacent → `../Resources` (Helpers CLI) → `Bundle.module` (dev/test). New resource loads must use it, and `Scripts/wi2-relocation-check.sh` must keep passing.
19. **One product version, single-sourced.** `AISidecarVersion.current` feeds CLI `--version`, the GUI About/Settings cards, and the build script's `CFBundleShortVersionString` injection (cross-checked at assembly). Never hardcode a product version elsewhere; sidecar/report engine and recipe schema versions are distinct and must not be conflated with it.
20. **GUI durable state is sidecar-only by default — no database file** (AC4-025, until M10's experimental opt-in). GUI state lives in `.ai.json`/XMP/session files, `config.json`, UserDefaults, and `~/Library/Application Support/CupricAspect/`; nothing is ever written inside the app bundle. `Scripts/m8-kill-relaunch-check.sh` asserts this.
21. **Derivative-cache coordination is one protocol.** Encode and hash derivative bytes outside the manifest lock — staged bytes before commit, and cached-hit verification under a shared inode lease; perform the final artifact rename and manifest mutation under `FileLock` on the persistent cache lock file. Every returned cache artifact holds an inode lease until its consumer releases it, and eviction/purge may delete only after taking a nonblocking exclusive inode lock. Keep manifest writes write-through and cross-process cache invalidation inode-aware; do not add an uncoordinated cache mutation path.
